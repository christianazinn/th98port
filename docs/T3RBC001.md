# T3RBC001 local rollback coordinator

Status: implemented as the phase-N0 synchronous proof owner for ordinary active
MAIN gameplay. It has no socket, peer, middleware, room, or product UI.

## Ownership and publication

`MainRollbackCoordinator` owns one live `MainProcess`, sixteen preallocated
`T3RBM001` boundary slots, and one reusable recovery image. A caller can:

- advance one confirmed input once;
- execute one private prediction, restore, then execute its corrected input;
- restore any still-retained pre-frame boundary; and
- compose or drain semantic audio only after the public call returns.

The wrong predicted execution is synchronous and private. No surface handle,
audio-drain callback, observer, host clock, or platform endpoint is invoked
between its step and restore. Only the corrected/latest process can be composed
or drained. This proves the required output-suppression seam without changing
ordinary gameplay or enabling a network route.

Restoring an older retained frame immediately invalidates every newer slot.
Expired frames fail closed after the sixteen-slot ring wraps. Every operation
uses caller-independent heap memory allocated when the coordinator is created;
ordinary advance/restore performs no coordinator allocation.

The production netplay owner will still need asynchronous confirmation and the
specified responsive one-shot-SFX event journal. This synchronous N0 owner
intentionally suppresses all private-prediction audio; it does not claim to be
the final network audio policy.

## Memory and throughput

On GCC x64, each tagged ring slot is 635,000 bytes. The ring is 10,160,000
bytes and reusable recovery is 634,988 bytes, for 10,794,988 bytes of retained
rollback storage plus small owner/allocation metadata.

An optimized MSVC x64 engineering probe ran 500 iterations of a deliberately
wrong frame followed by restore/corrected execution and a second restore to the
same benchmark boundary. Three measured runs were 2.7448, 2.7469, and 2.7533 ms
per iteration. The median conservative path is about 6.45 times faster than one
17.7232 ms source deadline despite including the extra benchmark restore.
These are development-host measurements, not a minimum-machine acceptance
claim.

## Verification

The cross-compiler test runs wrong-prediction/restore/correction on 48
consecutive VS frames, wrapping the ring twice. Every corrected frame equals an
uninterrupted twin in boundary facts, canonical simulation hash, all 256,000
composed pixels, and every semantic audio command. A speculative shot corrected
to movement leaves no sound command. A retained recent frame restores and
resimulates to the same final state; an expired frame and abandoned future both
fail closed.
