# T3RBV001 shared visual rollback state

Status: implemented for `Raster` and `Tram`. This is a local presentation
section of the future complete T3RBK001 boundary image; private MAIN presenters,
process-driver latches, and semantic feedback remain outside it.

## Contract

`T3RBV001` is never a replay, network packet, or peer-authoritative state. It is
the field-wise local image used to restore the two PC-98 graphics pages and text
machine before rollback resimulation. Capture writes into caller-owned storage,
restore reuses the Raster's existing vectors, and neither operation copies a C++
object image or allocates.

The fixed `RollbackVisualSnapshot` envelope is 520 KiB plus its 32-bit active
length. Its active prefix is 528,328 bytes:

| Offset | Size | Field |
|---:|---:|---|
| 0 | 8 | `T3RBV001` |
| 8 | 2 | version 1 |
| 10 | 2 | header size 32 |
| 12 | 4 | active image bytes |
| 16 | 4 | payload bytes |
| 20 | 4 | payload FNV-1a integrity check |
| 24 | 4 | section flags; bit 1 means shared visual state |
| 28 | 4 | reserved zero |
| 32 | 512,000 | page 0 then page 1, one Index4 byte per pixel |
| 512,032 | 3 | access page, shown page, raster mode |
| 512,035 | 48 | pending RGB8 palette |
| 512,083 | 48 | applied RGB4 palette |
| 512,131 | 2 | raw signed PaletteTone bit pattern |
| 512,133 | 2 | logical vertical scroll |
| 512,135 | 1 | TRAM visibility |
| 512,136 | 8,000 | 2,000 little-endian code/attribute cell pairs |
| 520,136 | 8,192 | all 256 mutable 16x16 gaiji glyphs |

Restore validates the complete image before changing either owner. It rejects
bad headers, sizes, checksums, reserved fields, non-Index4 pixels, invalid page
or raster-mode values, non-RGB4 applied colors, and non-Boolean visibility.
Pending versus applied palette state, hidden pages, invisible TRAM contents,
and unreferenced mutable gaiji are intentionally preserved.

## Frozen vector and measurements

The cross-compiler fixture has active size 528,328 and payload FNV-1a
`1721220782`. GCC and MSVC restore and recapture it byte-identically; a
valid-checksum invalid pixel is rejected without mutating the destination.

A 16-slot visual ring reserves 8,519,744 bytes. Together with the implemented
simulation section it reserves 10,092,672 bytes, about 9.63 MiB, before the
remaining presenter/process section.

On the development Ryzen host, a 50-iteration optimized GCC measurement was
approximately 0.390 ms per capture and 0.478 ms per validated restore. These are
engineering measurements, not minimum-machine acceptance results.
