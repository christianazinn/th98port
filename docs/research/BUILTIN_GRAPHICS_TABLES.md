# TH03 built-in graphics tables

Status: source-backed audit, 2026-08-09. This note identifies the visual data
which remains after the caller-owned RGB/PI/CDG/BFNT/MRS files described in the
asset inventory have been decoded. It is a planning input only: it copies no
original bitmap, text, or generated-table bytes.

## Authority and scope

All citations name the clean Anniversary source object
`3e2381d4275be7287f5525de5c95389d492b0a3c`, pinned in
[`../SOURCES.lock`](../SOURCES.lock). `Tupfile.lua:601-610` defines the three
TH03 source BMP-to-ASM inputs; `Tupfile.lua:740-748` links their wrappers and
the adjacent MAIN data modules. This audit read the complete definitions and
their direct consumers, not only the build list.

The result is deliberately smaller than the term “built-in graphics” implies:

- There are exactly three compiled 1bpp mask families: the score font,
  pellets, and staff-roll flakes.
- Enemy, explosion, hit-circle, shot, Boss, defeat, HUD-start, result, and
  warning *patterns* mostly live in decoded BF2/MRS/BFT assets, in the loaded
  Sprite16 staging area, or are generated by source geometry. The remaining
  code-linked values are slot/layout/mask/text tables, not more bitmap data.
- Bullet-pattern and CPU-dodge tables in `pbpat[data].asm` are gameplay data.
  They stay in `th03_core`; a presenter consumes resulting facts and must not
  duplicate them as “visual assets”.

### Distribution finding

The donor has no project-root license file. Its `bin/COPYING.GPLv2` applies to
the listed bundled build tools, as documented by `bin/README.md`, not to TH03
source, reconstructed source BMPs, or original game art. The tracked BMPs are
source-published (`git log --follow` identifies their reconstruction commits),
but that alone is not a redistribution licence for this port. The generated
`*.asp` files are ignored build products (`.gitignore:*.[ac]sp`). Therefore no
visible source bitmap or Japanese string below should be copied into this
repository or a distributed native binary on the assumption that it is
licensed by ReC98.

The safe default is an external, user-supplied Authentic content import that
creates an ignored cache. Small *non-content* numeric/control constants may be
re-expressed from the cited program semantics in native code, with focused
tests. A later product licensing decision can explicitly change that policy.

## Actual compiled mask families

| Family and exact source form | Source consumer and required operation | Native content disposition |
|---|---|---|
| **Score font** `sSCORE_FONT`: 10 1bpp `8x8` `DotRect`s. `th03/sprites/score.hpp:5-7` calls the source rows “stored upside down”; the ignored generated sheet declares 10 sprites. `Tupfile.lua:602` generates it from `th03/sprites/score.bmp` with `-u`, and `sfntdat.asm:7-8` links it with the score support table. | `SUB_D50E()` indexes one digit at `8` bytes, starts at destination row 6, and emits exactly seven writes while walking VRAM upward (`th03/main/player/scoreblt.cpp:6-26`); stored byte 7 is unread. `sub_D52E()` invokes it for both scores and the continue count (`score_rn.asm:49-104`); five-digit point routines use the same blitter (`score.cpp:82-158`). This is a single-colour GRCG/RMW mask draw, not TRAM text. | **External generated/imported mask.** The importer should preserve all eight stored rows and expose ten named digit cels; the presenter consumes rows 0 through 6 exactly. Do not store donor BMP/ASP bytes in tracked fixtures. |
| **Pellets** `sPELLET`: two logical cels (`C_PELLET`, `C_PELLET_TRANSFER`), each an `8x4` logical mask represented as `PRESHIFT * 2 == 16` pre-shifts. Each stored variant is four `dots32_t` rows, hence 16 bytes; the complete generated sheet has 32 `32x4` stored sprites. `pellet.h:3-17`, `planar.h:13-22`, and `Tupfile.lua:610` are the format authority; `peldat.asm:7-10` links it. | `grcg_pellet_put()` chooses the stored variant with `left & 15`, then emits four 32-bit planar writes; the narrow path writes the equivalent 16-bit prefix (`th03/main/bullet/bullet.cpp:715-760`). The bullet renderer selects the normal or transfer cel in its ordinary pellet path (`bullet.cpp:1699-1716`). The pre-shifts are part of the source artifact; recomputing a shift at draw time is not automatically equivalent at edges. | **External generated/imported mask.** Import the source-generated representation or generate it from the external canonical content before runtime. Keep both cels and all 16 variants; validate full and narrow writes with synthetic masks. |
| **Staff-roll flakes** `sFLAKE`: four cels, each an `8x8` logical mask stored as eight `dots16_t` rows (`16x8`, 16 bytes per cel; the upper/lower padding supports word loads). `flake.h:3-11`, `Tupfile.lua:606`, and `mainl/flds[data].asm:1` are the data/build authority. | `flake_put()` rotates each 16-bit source row right by `left & 7` and ORs it into the B plane for all eight rows (`th03/end/staff.cpp:33-63`). `stf_bclr.cpp:16-151` owns 80 flake records, source spawn/update order, the blue-plane clear, page show/access flip, and the documented 80-to-50 reset. `stf_drv.cpp:89-218` supplies the staff-roll schedule and seeds its local sequence from `resident->rand`. | **External generated/imported mask.** The native parcel must reproduce the 16-bit rotate-and-OR result, not generic alpha replacement. The flake lifecycle is presenter/application state, not core state. |

`FIVE_DIGIT_POWERS_OF_10` is adjacent to the score font but is not graphical
content: it is exactly five `uint16_t` divisors (`5_powers_of_10[data].asm:1-2`)
used by score conversion and point rendering (`score.cpp:5-158`). Re-express it
as a named five-element native constant in the score-draw parcel; it has no
importer or asset identity.

| **CDG dissolve masks** `CDG_DISSOLVE_PATTERN` | Eight strength rows of four `uint16_t` masks (`formats/cdg_put_dissolve[data].asm:1-11`). | **Horizontal-flip lookup** `hflip_lut` | A generated 256-entry `dots8_t` bit-reversal table (`formats/hfliplut[bss].asm:1-2`, `formats/hfliplut.h:7-11`). `hflip_lut_generate()` fills it deterministically before MAIN and MAINL use (`hfliplut.cpp:6-29`, `main/rstart.cpp:75-80`); CDG horizontal put and persistent MRS flipping consume it (`formats/cdg_put.asm:95-140`, `formats/mrs.cpp:233-245`). | **Generate in native code.** Do not import or serialize it; validate all 256 entries and keep the table entirely in `th03_assets`/`th03_present`, never core. |

## Compiled TRAM/text tables

These are visual data, but their glyph images are in the decoded gaiji/BFNT
font, not in the tables themselves. Preserve their raw byte/glyph-ID semantics
for the Authentic profile; localization may map the *semantic* label to another
profile only after it preserves timing, cell span, and layout.

| Table | Exact form and direct consumer | Disposition |
|---|---|---|
| `gsHIT`, `gBONUS_BOX`, `aBONUS_BOX_SPACES` | Two NUL-terminated gaiji-ID sequences of 2 and 4 IDs, plus an eight-ANK-space erase string (`main/player/combo[data].asm:1-4`). `combos_update_and_render()` places/erases them through `gaiji_putsa()`/`text_puts()` (`combo.cpp:105-184`). | **Source-derived UI layout constants.** The gaiji bitmaps remain a decoded `GAMEFT.BFT` concern. |
| Warning sequences `gbWARNING_1..3`, `gp*` | Three 16-gaiji rows and four NUL-terminated gaiji strings of 11, 8, 8, and 14 IDs in `warn[data].asm:7-31`. The warning renderer selects the source attributes and exact TRAM rows (`player/warning.cpp:96-120`). | **Source-derived UI layout constants.** Use typed label/gaiji sequences, not an assumed Unicode string. |
| Result text `aMAX_COMBO` through `aPLAYER_REM` | Nine NUL-terminated Shift-JIS/ANK labels in `rtextdat.asm:8-34`; `sub_E3F2()` selects their rows and status-dependent subset (`player/shot.cpp:155-179`). | **External Authentic text content or an explicitly licensed profile.** It is visible language content, not a gameplay table. Preserve source byte/glyph behaviour for Authentic; do not silently bake a translated string into Classic core. |
| Static HUD gaiji names | `hud_static_put()` uses named hearts, bombs, Thalia, yin-yang, and proportional gauge/Boss digits (`main/hud/static.cpp:7-142`). It contains no bitmap table; those glyphs come from the gaiji font loaded by the application. | **Already file-backed.** Extend the BFNT/gaiji loader/compositor, not `th03_core` or a new source-byte table. |

## Deliberate non-assets and boundary exclusions

- `pbpat[data].asm` contains angles, bullet-group choices, CPU-dodge route
  tables, and a Yumemi group order. Its consumers calculate projectile and CPU
  mechanics (`main/player/ch_shot.cpp:49,1092`, `main/player/c568.cpp:12-161`,
  `main_03q.cpp:43,307`, `main/player/yumemi_bomb.cpp:15,54-75`). It is
  deterministic gameplay authority already represented by the core audit, not
  a presentation import.
- `gba_hitc_enemy[data].asm` also contains `a00ch_bf2`, a *filename template*
  for the decoded character BF2/MRS transaction, alongside the gauge mask. It
  is not a hidden image blob (`hitc_mrs.cpp:25-65`).
- Contract-listed BSS/data such as `soch_data`, `hitcircle_bss`, warning flags,
  HUD-start records, combo state, foreground shifts, and character visual BSS
  must become typed presenter state only where they control pixels. Never copy
  a DGROUP image or add this state to `th03_core` hashes. The exception is an
  already-audited core compatibility schedule/RNG read, which remains in core
  even when its particles are presenter-owned.

## Dependency-ordered implementation parcels

1. **PRESENT-BUILTIN-MONO-INPUT.** Add a small immutable, caller-provided
   1bpp-mask model in `th03_assets` or a presenter-private import adapter:
   10 score glyphs, 2×16 pellet variants, and 4 padded flake cels. It accepts
   spans supplied by an external Authentic importer and has synthetic-only
   malformed-size/row-order tests. No filesystem path, donor bytes, or core
   dependency.
2. **PRESENT-DIRECT-MASK-OPS.** Implement the three source operations against
   the existing planar raster: score GRCG/RMW rows, pellet pre-shift selection
   with 32-bit/full and 16-bit/narrow semantics, and flake 16-bit rotate/OR on
   the B plane. Hand-authored 1bpp fixtures must test every edge/shift and
   prove that operations affect only the access page.
3. **PRESENT-SPRITE-STAGING.** Add a private atlas/staging transaction that
   retains MAINL's decoded PI page content, applies decoded BF2
   `sub_E266()`/source slot placement,
   duplicates the 640x200 sprite area to the opposite page, and records the
   alpha-generation boundary. Keep separately allocated MRS out of the atlas.
   Translate `SO_*` and `ccorddat` into typed local
   slot/layout constants. Do not expose PC-98 offsets as the Arrange API.
4. **PRESENT-SPRITE16-SEMANTICS.** Implement only the used Sprite16 behaviours:
   source-atlas alpha preparation, normal clear overlap, OR overlap, mono
   colour, clipping in 16-pixel columns, and the downward-column variant.
   Cover enemies, explosions, hit circles, shots, and loaded BF2 result cels
   with synthetic atlases before wiring live observations.
5. **PRESENT-UI-GEOMETRY.** Port the gauge terminal-mask draw, result masked
   triangles, static/dynamic score, combo, warning, and result-label layout as
   presenter-only code. Re-express non-content masks/coordinates with named
   fixed-width values; consume decoded gaiji/BFNT glyphs and externally
   supplied Authentic text.
6. **PRESENT-STAFF-FLAKES-AND-CDG-DISSOLVE.** Port the 80-record flake state,
   spawn/update, blue-plane clear, CDG dissolve mask, CDG ordering, and page
   flip from `stf_bclr.cpp`/`stf_drv.cpp`; seed scene-local presentation RNG
   from the explicit resident handoff. This is independent of gameplay replay
   verification.
7. **PRESENT-VISUAL-ORACLE.** Capture raw two-page planar, palette, TRAM,
   scroll, and operation traces at selected Anniversary frames. Gate each
   parcel by first-operation/first-plane-byte divergence; headless core must
   remain exact with no observer and with a discard observer.

## Authority gaps and required validation

1. The pixel content of the three generated masks is observable, but their
   `*.asp` outputs are ignored rather than source-locked. The pinned `*.bmp`
   inputs and exact `bmp2arr` arguments are sufficient reconstruction
   authority, but a product importer needs an explicit content-provenance and
   licensing decision before distribution.
2. `SUB_B3A2()` and `SUB_B3F6()` are raw emitted PC-98 EGC/VRAM sequences in
   otherwise readable source (`hitcirc.cpp:47-140`). Their intended raster
   result is partly evident, but a host translation must not claim pixel parity
   until a raw-page capture checks the EGC copy and partial gauge word.
3. The full `SPRITE16.COM` implementation is present as third-party assembly,
   and the TH03 adapter documents the used calls, but the current native raster
   foundation intentionally lacks general unaligned Sprite16/EGC semantics.
   `libs/sprite16/sprite16.h:12-50`, `main/sprite16.cpp:13-156`, and the visual
   capture gate—not an inferred alpha rule—are the authority for that parcel.
4. No source or decoder gap was found for the PI, BF2, or MRS content itself:
   it is file-backed and already belongs to decoded-asset paths. Only PI and
   BF2 feed the Sprite16 atlas; MRS stays separately allocated. The open work
   is ordering and raster operation fidelity, not reverse-engineering a second
   compiled graphic table.
