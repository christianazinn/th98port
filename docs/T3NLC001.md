# T3NLC001 New Classic netplay match contract

`T3NLC001` is the platform-neutral identity of one locked New Classic direct
match. It exists before MAIN, a socket backend, or the source scheduler. The
host owns the P1 selection, rank, seed, and source cadence; the joiner owns the
P2 selection. Neither side can produce a final contract until both locks are
present and valid.

## Exact wire

The canonical value is 32 little-endian bytes:

| Offset | Type | Meaning |
|---:|---|---|
| 0 | `char[4]` | `T3NC` |
| 4 | `uint8` | Schema version, exactly 1 |
| 5 | `uint8` | Rank, 0..3 |
| 6 | `uint8` | P1 base character, 1..9 |
| 7 | `uint8` | P1 palette, 1..2 |
| 8 | `uint8` | P2 base character, 1..9 |
| 9 | `uint8` | P2 palette, 1..2 |
| 10 | `uint8[2]` | Reserved zero |
| 12 | `uint32` | Host seed |
| 16 | `uint32` | Source-cadence ticks |
| 20 | `uint32` | Source-cadence seconds |
| 24 | `uint32` | New Classic netplay ruleset, exactly 1 |
| 28 | `uint8[4]` | Reserved zero |

Character and palette IDs deliberately use the existing source numeric domain
without importing presentation objects into the backend-neutral protocol
library. The ruleset version binds New Classic's deterministic gameplay policy;
local volume, language, window, filtering, and other presentation settings do
not belong in this value.

Ruleset 1 includes New Classic's three-digit combo presentation policy; the
CLI applies it before MAIN construction. The current UDP handshake carries the
nonzero FNV-1a-64 projection of these
exact 32 bytes. Frame zero separately exchanges SHA-256 over the complete
canonical simulation image, so a content/build defect cannot hide behind a
64-bit contract projection. A future room or WebRTC backend must construct the
same value; it must not redefine match ownership in transport-specific code.

Golden vector for P1 Reimu/first, P2 Mima/second, Normal, seed 34, nominal
PC-98 cadence:

```text
54 33 4E 43 01 01 01 01 02 02 00 00 22 00 00 00
EB 07 08 00 70 24 00 00 01 00 00 00 00 00 00 00
FNV-1a-64 = 4154EA41F3912F3A
```
