# T3NET001 owned-player input

`T3NET001` freezes the smallest gameplay value exchanged with a New Classic
rollback backend. It is post-device, post-KeyConfig logical input for exactly
one player. It is not a complete network packet and contains no transport,
clock, frame, player identity, system input, raw device input, or application
event.

## Wire value

The value is exactly four bytes:

| Offset | Type | Meaning |
|---:|---|---|
| 0 | `uint16_le` | Player logical input word |
| 2 | `uint8` | Charge held (`0` or `1`) |
| 3 | `uint8` | Reserved; must be zero |

The only accepted input-word bits are `0x0F3F`: the six source cardinal/button
bits plus the four source diagonal bits. Every other bit, a Charge value above
one, a nonzero reserved byte, or a wire of any other length fails closed.

Golden vector:

```text
word=0x0F25, charge=1  ->  25 0F 01 00
```

## Ownership and composition

The player slot is supplied by the already-agreed match contract, not encoded
inside this four-byte value. Applying a P1 value changes only `CoreInput.p1`
and Charge bit 0. Applying a P2 value changes only `CoreInput.p2` and Charge
bit 1. Neither may change the other player's lane or `CoreInput.system`.

Combining independently validated P1 and P2 values begins from a zero
`CoreInput`. Source-global Pause/Restart/application input remains local
phase-control policy and is never accepted through the predicted gameplay
input stream.

## Compatibility boundary

This schema is implemented by `new_classic_netplay_protocol.hpp`. A future
frame packet may carry this value alongside its own frame and reliability
metadata, but must not reinterpret these four bytes. Any incompatible input
change requires a new negotiated protocol revision.
