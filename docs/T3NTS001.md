# T3NTS001 deterministic netplay scheduling proof

`T3NTS001` is the pre-middleware scheduling contract for New Classic netplay.
It proves transport disorder and rollback-input resolution without using a
socket, host clock, network thread, game process, or UI.

## Opaque transport simulator

`NewClassicNetplayTransportSimulator` owns a fixed queue of 256 opaque
datagram copies with a 1200-byte maximum payload. Construction allocates the
queue once; later send and receive calls allocate nothing.

Each send receives an explicit deterministic plan:

- primary delay in logical host frames;
- optional primary loss;
- optional delayed duplicate copy.

Delivery selects the earliest due logical frame and then the original enqueue
order. The simulator assigns one stable datagram ID to the primary and all its
duplicate copies. It does not decode T3NET001 or implement reliability. The
real rollback backend will remain responsible for packet acknowledgement and
retransmission policy.

## Owned-input timeline

`NewClassicNetplayInputTimeline` owns 64 tagged frame slots for one peer. The
local P1/P2 role is fixed at construction. Local and remote values are strictly
validated T3NET001 values.

For each executable frame:

1. use exact remote input if known;
2. otherwise repeat the preceding resolved remote input;
3. use neutral only when frame zero has no remote value;
4. stop before the thirteenth unconfirmed frame.

A late input that differs from the value used by an executed frame requests
the earliest mismatch. Rewind preserves actual local/remote values, discards
only executed resolution, and recomputes the affected suffix. Confirmation is
the contiguous count of executed frames whose local and remote actual values
are both known and whose resolved remote value is exact. A newer exact packet
cannot move that frontier past an older missing frame or bypass the prediction
cap.

Duplicate identical submissions are idempotent. A conflicting duplicate,
invalid input, unavailable rollback boundary, stale retained-state access, or
out-of-window future frame fails closed (late duplicates older than retained
confirmed history are explicitly ignored).

## Evidence and boundary

The cross-compiler proof sends 48 P1/P2 frames through different delay
patterns, deliberate primary drops with later copies, duplicates, and reorder.
Both peer timelines predict and rewind, then confirm all 48 frames with the
same exact combined `CoreInput` at every frame.

This is not a production rollback session. It does not yet step
`MainRollbackCoordinator`, deduplicate speculative audio, commit replay rows,
hash confirmed state, or expose a real network packet/API. Those are the next
N1 integration boundary.
