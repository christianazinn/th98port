# T3NID001 authenticated netplay identity snapshot

`T3NID001` freezes the presentation identities selected by the authenticated
room service. It is not simulation state. Both peers receive the same value,
carry its SHA-256 once in `T3NLC001`, and reject a mismatch before MAIN begins.
Direct UDP carries an all-zero identity digest and retains the source character
titles.

## Exact wire

The canonical account value is 224 bytes:

| Offset | Type | Meaning |
|---:|---|---|
| 0 | `char[8]` | `T3NID001` |
| 8 | `uint8` | Identity kind, exactly 1 (authenticated account) |
| 9 | `uint8` | P1 nametag byte length, 1..57 |
| 10 | `uint8` | P2 nametag byte length, 1..57 |
| 11 | `uint8` | Reserved zero |
| 12 | `uint8[16]` | Room UUID in network byte order |
| 28 | `uint8[16]` | P1 account UUID in network byte order |
| 44 | `uint8[16]` | P2 account UUID in network byte order |
| 60 | `char[57]` | P1 printable-ASCII nametag, zero-padded |
| 117 | `char[57]` | P2 printable-ASCII nametag, zero-padded |
| 174 | `uint8[18]` | Reserved zero |
| 192 | `uint8[32]` | SHA-256 of bytes 0..191 |

UUID input is canonical lowercase hexadecimal with hyphens. The UUIDs must be
distinct. Each nametag must reproduce the exact two-by-28-cell whole-word
layout accepted by the New Classic nametag validator. Changing the room,
either account, or either name changes the digest. The value is immutable after
authenticated room/queue entry, so a later rename affects only future matches.

The initial implementation does not yet serialize this block into V13. That
typed replay tail is a separate compatibility parcel; the live match agreement
does not depend on replay support.
