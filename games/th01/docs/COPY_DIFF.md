# `th01-port/` — the diff of the copy

2026-09-07 continuation: the historical copy below now lives in
`native-port/games/th01/`. `CORE_FOUNDATIONS.md` records the first intentional
gameplay additions: `th01_core`, its tests, and the shared `pc98_numeric` target.
The CMake additions wire those targets and support direct per-game builds;
they are not verbatim TH03 copies. Existing renderer and SDL copy provenance
below remains historical evidence.

The standalone skeleton test now explicitly requests C++23 at target level,
so combined builds do not depend on the per-game preset setting that default.

`[measured 2026-08-19, PORT-W5A-TH01-TREE2, lane g4-th01]`

W5a step 3 is "create `th01-port/` by copying `th03-port`'s CMake skeleton, its
`th03_add_test()` (renamed `th01_add_test()`), and the six no-TH03-identifier
libraries, unmodified. **Diff the copies. Extract nothing.**"

`PORT-W5A-TH01-TREE-PRECHECK` established, before any tree existed, that five of
those six library names name nothing: they occur in exactly one file in the
repository, the plan that proposes them. One of six was copyable —
`th03_platform_sdl`. This document is the second half of the instruction: the
diff.

Its headline is that **the copy of that one library does not stand up either**,
and the two facts that make that true are both things only a copy could have
shown.

## 3. What the diff found — two content-level rename failures

The three-token rename is a *lexical* operation. Both findings below are places
where the donor text contains TH03 with no `th03` token in it, so no rename
however careful could have reached them. Both were found by copying and looking,
which is the entire argument for copy-first.

### 3.1 `.gitignore` — the rename changed 0 of 4 lines, and 2 of 4 were wrong

```
/out/            game-neutral
/.scratch-*      game-neutral
/YUME.CFG        TH03's config file
/YUME.NEM        TH03's score file
```

A game's session files carry the *game's* names, not the port's prefix. The copy
therefore ignored two files TH01 never writes and tracked the five TH01 does.
Measured from ReC98, and each confirmed to be a file the game **writes**, not
merely reads: `CFG_FN` in `th01/formats/cfg.hpp`, opened `"wb"` by `cfg_save()`
in `th01/op_01.cpp`; and `SCOREDAT_FN_EASY` … `_LUNATIC` in
`th01/shiftjis/fns.hpp`, opened `"wb"` through `scoredat_create()` in
`th01/fuuin_02.cpp`.

```
/reiiden.cfg
/REYHIES.DAT
/REYHINO.DAT
/REYHIHA.DAT
/REYHILU.DAT
```

This is the smallest file in the whole copy — four lines — and it was already
half wrong. **Fixed in the copy**, because `.gitignore` is tree infrastructure
rather than ported game content: a wrong one silently ignores files the port
must track, and it has no donor-diff value to preserve.

### 3.2 `th01_product_window_title` still says "The Phantasmagoria of Dim. Dream"

`include/th01/platform/sdl_platform.hpp` now declares

```cpp
inline constexpr std::string_view th01_product_window_title =
	"The Phantasmagoria of Dim. Dream";
```

— a TH01-prefixed identifier bound to TH03's product name, and the copied
`tests/test_platform_sdl_platform.cpp` asserts that exact string.

**There is no TH01 value to substitute, and that is itself the finding.** ReC98's
TH01 sources contain no product or window title, because a PC-98 DOS binary has
no window to title. `th03_product_window_title` is a constant the *port* invented
for its SDL window. Searching ReC98's `th01/` for "Responsive" returns exactly
one hit, `th01/shiftjis/op.hpp` — and it is a **music-track label** inside
`MUSIC_TITLES`, not a product string. (This document's first draft cited that
line as TH01's title. It is recorded here because a plausible-looking grep hit
that answers a different question is precisely the failure a copy-then-diff pass
is supposed to catch.)

So TH01's window title is a port *decision*, not a lookup — the first item of
design work this tree surfaced.

**Deliberately NOT fixed.** The distinction against §3.1 is not taste: this
constant is *inside the copied library*, and the copy's whole value is that it
diffs cleanly against its donor. Editing content inside it destroys that
property to save one line of work that belongs to the port proper. It is
recorded here as item one of the port's own backlog.

That two of these exist in a 4 863-line copy of a library specifically chosen as
"measured free of TH03 identifiers" is the calibration to carry forward: **"free
of TH03 identifiers" is a statement about tokens, and a port is not a token
substitution.**

## 4. The skeleton's self-test, and why the tree has one at all

Every copied test is behind `TH01_ENABLE_SDL`, which is `OFF` by default. A
`th01-port` consisting only of the copy therefore builds **zero targets and runs
zero tests** in its default configuration, and every gate over it is green
forever. That is the "check over an absent set" shape from this campaign's
false-green catalogue, and it would have been the first thing this tree taught
anyone.

`tests/test_skeleton.cpp` is the one call site that builds by default. It asserts
the two terms of the skeleton's compile contract that a translation unit can
observe, and says out loud that the third is checked elsewhere:

| contract term | checked by | control |
|---|---|---|
| C++23 library mode reached the target | `__cpp_lib_expected >= 202202L` in the test | compiled by hand at `-std=c++20`: FAILS, naming that assertion |
| `CXX_EXTENSIONS OFF` reached the target | `__STRICT_ANSI__` in the test, GCC/Clang only | compiled by hand at `-std=gnu++23`: FAILS, naming that assertion |
| the warning set and `-Werror` reached the target | the generator's `flags.make`, §5 | a deliberate narrowing conversion at those flags: **rejected**, `-Werror=conversion` |

### 4.1 Why a feature-test macro and not `__cplusplus`

The first draft of this test asserted `_MSVC_LANG >= 202302L` and **failed on
MSVC**, on a build whose CMake files were correct. Measured, MSVC 19.41 (VS 2022
toolset 14.41) compiling at `stdcpplatest` — which is exactly what CMake emits
for `cxx_std_23` and for `CMAKE_CXX_STANDARD 23`:

```
_MSVC_LANG  = 202004     C++20 plus the working draft; never 202302
__cplusplus = 199711     /Zc:__cplusplus is not in the skeleton
```

Neither version macro can witness C++23 on this toolset, so an assertion on
either is a demand no correct build file can satisfy. `__cpp_lib_expected` is
**202211 on both compilers here**, and `std::expected` is what the copied library
is actually built on — 32 occurrences across its six translation units and
headers. Asserting the capability the code depends on, instead of a version
number standing in for it, is the difference between measuring the build and
measuring the vendor's macro policy.

The `__cplusplus = 199711` reading is inert *today*: the only `__cplusplus` uses
anywhere in `th03-port`'s sources are the two `extern "C"` guards in
`src/audio/pmd_shim.h`, which are correct at any value. It stops being inert the
moment a copied header feature-gates on it under MSVC.

## 6. The finding: the one copyable library of six is not self-contained

This is what the copy was for, and it changes the answer the precheck gave.

`th03_platform_sdl` was chosen because its sources carry no TH03 identifiers.
They do not. But its **public headers include three headers owned by three other
libraries**, and the transitive closure of those is 14 headers across five
targets:

| copied header | includes | closure |
|---|---|---|
| `platform/sdl_audio_device.hpp` | `audio/fixed_resampler.hpp` | → `audio/pmd_opna.hpp` |
| `platform/sdl_input.hpp` | `app/tick_input.hpp` | → `core/game.hpp` → `core/numeric.hpp`, `core/observer.hpp`, `error.hpp` |
| `platform/sdl_platform.hpp` | `app/host_surface.hpp` | → `present/source_surface.hpp` → `present/text.hpp` → `present/raster.hpp`, `present/tram.hpp` → `present/planar.hpp`, `assets/types.hpp` |

and its CMake declaration says so out loud, in the region copied verbatim:

```cmake
target_link_libraries(
	th01_platform_sdl
	PUBLIC th01_app_runtime th01_audio_pmd SDL3::SDL3-shared
)
```

`th03_app_runtime` links `th03_present`, which links `th03_core` and
`th03_assets`. **Following the copied library's own link line reaches 60
translation units of TH03 gameplay, presentation and audio code.** Counted from
the generator's own `DependInfo.cmake` object lists rather than by reading the
source lists — `src/core/` in particular *looks* like 34 entries in
`CMakeLists.txt` and is 7 translation units, because 27 of those entries are
`.inl` files included into `frame.cpp`:

| target | TUs |
|---|---|
| `th03_present` | 34 |
| `th03_core` | 7 |
| `th03_assets` | 5 |
| `th03_app_runtime` | 4 |
| `th03_audio_pmd` | 4 |
| `th03_vendor_ymfm` | 4 |
| `th03_vendor_98fmplayer` | 2 |
| **total** | **60** |

### 6.1 The control

Compiled by hand, `-std=c++23 -fsyntax-only -Iinclude -Isrc/platform`, on each
copied translation unit:

```
sdl_audio_device.cpp  fatal error: th01/audio/fixed_resampler.hpp: No such file or directory
sdl_input.cpp         fatal error: SDL3/SDL_events.h: No such file or directory
sdl_platform.cpp      fatal error: th01/app/host_surface.hpp: No such file or directory
```

Two of the three fail on a **port-internal** header before SDL is even reached.

### 6.2 Why this is not just "copy those too"

Twenty distinct foreign symbols are referenced. Four need link-time definitions,
and they land in the two files this campaign has already ruled out for TH01:

| symbol | defined in | prior ruling |
|---|---|---|
| `app::source_surface_to_host_rgba` | `src/app/host_surface.cpp` | — |
| `app::integer_letterbox_8x5` | `src/app/host_surface.cpp` | — |
| `app::physical_input_source_count` | `src/app/tick_input.cpp` | `TH01_PORT_SCOPE.md` §5.5: `tick_input.hpp` assumes **one** logical action vocabulary for the whole game; TH01 does not have one |
| `present::set_source_surface_oracle_hashes_enabled` | `src/present/source_surface.cpp` | `W5A_TH01_PLAN.md` §3.2: encodes the two-page GRCG model, which **does not describe TH01 at all** |

So the closure is not a matter of copying more files. Two of the four link-time
dependencies are on the exact two modules already measured as wrong for TH01.

**CORRECTED `[re-measured 2026-08-19, PORT-W5A-TH01-RENDERER-MODEL]`. Both
halves of that paragraph are wrong, and the table has one row that does not
belong in it.**

- **`app::physical_input_source_count` is not a link-time dependency and is not
  defined in `tick_input.cpp`.** It is `inline constexpr std::size_t` at
  `th03-port/include/th03/app/tick_input.hpp:46`, a header constant.
  `src/platform/sdl_platform.cpp` does not reference it anywhere; its only
  platform-layer use is `include/th03/platform/sdl_input.hpp:22`. The row was
  built by reading a header closure as if it were a link line.
- The measured link-time set for `sdl_platform.cpp` is therefore **three**:
  `source_surface_to_host_rgba` (`:353`), `integer_letterbox_8x5` (`:580`),
  `set_source_surface_oracle_hashes_enabled` (`:247`, `:518`). Widening to the
  whole copied library adds one this table missed:
  `app::TickInputScheduler::push_live_event`, `src/platform/sdl_input.cpp:404`.
- The `source_surface` ruling in the last row **is refuted**, at the scope it
  was stated. `th01-port/docs/RENDERER_MODEL.md` §1.1 classifies the module
  entity by entity: 1 of 23 public entities is page-flip specific, **0** are
  TH03-specific, and the whole flip footprint is 3 lines / 118 B of 537 lines /
  15,460 B. The one remaining link-time dependency on it is
  `set_source_surface_oracle_hashes_enabled`, which is the oracle switch — not
  renderer semantics.

What survives unchanged is §6's actual finding: the copied library is **not**
free-standing, its public headers pull a 14-header closure across five targets,
and its own link line reaches 60 translation units. That is still true and is
still why "one of six is copyable" was the wrong conclusion. What is not true is
the reason given here for *why* the closure could not simply be followed.

### 6.3 It cannot be built here in any case

`TH01_ENABLE_SDL` is `OFF` by default, and turning it on requires an
authenticated SDL 3.4.10 source tree at `out/deps/SDL3-3.4.10`. That directory
does not exist, and the copied `tools/bootstrap_sdl3.ps1` is **offline by
construction** — it refuses to run without `-ArchivePath` naming an explicitly
acquired release asset, and verifies it against a pinned SHA-256. Acquiring that
archive is a human decision, not an agent's. So the SDL configuration of both
`th01-port` and `th03-port` is unbuildable on this host today, and every number
in §5.3 is from the default configuration.

### 6.4 One latent trap, recorded rather than papered over

The copied test block at `th03-port/CMakeLists.txt:834-857` passes
`STAGE_AUDIO_LICENSES` to `th01-platform-sdl-audio-tests`. That reaches
`th01_stage_audio_licenses`, copied verbatim, which stages
`third_party/98fmplayer/LICENSE` and `third_party/ymfm/LICENSE` — and
`th01-port/third_party/` does not exist. It is unreachable today for the reason
in §6.3, and it is left verbatim rather than edited for the reason in §3.2, but
it is the first thing that breaks when SDL is enabled.

## 7. What this means for W5a step 3

The precheck's answer was **one of six libraries is copyable**. Having copied it,
the answer is:

> **Zero of six are copyable as free-standing libraries.** The sixth compiles
> only against a 14-header closure spanning five TH03 targets, and links only
> against 60 translation units of TH03 gameplay, two of whose modules this
> campaign has already measured as not describing TH01.

What survives, and it is not nothing:

- **the CMake skeleton is portable verbatim** and proved so from generated
  output — 208 + 19 + 79 lines carried across at a 2.8% rename rate, emitting
  byte-identical compile flags on GCC and passing both compilers with
  warnings-as-errors;
- **`th01_add_test()` is portable verbatim**, and now has a call site that
  builds by default and two controls that show it is not vacuous;
- **the SDL platform code is a real starting point** for TH01's host layer, now
  in the tree and diffable, with its exact debt written down;
- **two rename failures and one link-closure result** that only existed to be
  found because the instruction was *copy, then diff* rather than *design*.

The next honest increment is not "copy `pc98_*`". It is to decide TH01's
renderer model (`W5A_TH01_PLAN.md` §8 already names it as W5a's single largest
unknown for TH01), because `present::source_surface` is what the copied platform
layer reaches for and it is the one module measured as not describing TH01.
