# T3RBM001 complete local MAIN rollback state

Status: implemented for one stable `MainProcess` gameplay boundary. The local
frame ring, speculative-output policy, and network scheduler are deliberately
separate owners and remain open.

## Contract

`MainProcessRollbackSnapshot` composes four already-owned sections without
copying any C++ object image:

1. the architecture-neutral `T3RBK001` deterministic simulation image;
2. the complete `T3RBV001` Raster/TRAM visual image;
3. the field-wise `T3RBP001` retained MAIN presenter state; and
4. process-local semantic state: input protocol, immutable run checks, the
   bounded undelivered audio-command queue, and source effect-arbitration slot.

The snapshot is local trusted memory. It is not a replay, peer message, save
file, or stable serialized ABI. Authenticated assets, pointers, host clocks,
SDL objects, PMD/YM2608 device state, files, threads, and network handles stay
outside it. Audio commands are rolled back before delivery; already submitted
host audio cannot be undone and therefore belongs to the future confirmation
policy.

Capture is accepted only at a completed ordinary MAIN gameplay boundary. It
rejects hidden replay preroll, a deferred recorded-pause frame, partial or
failed presentation, and failed semantic feedback. `version` remains zero if
capture does not complete.

## Transactional restore

Restore receives caller-owned recovery scratch so the source-tick path does
not allocate or put another approximately 620 KiB image on the stack. It
validates the wrapper, immutable process properties, every queued command, the
effect scheduler, presenter phase, and each encoded section before publishing
the result.

The live process is captured into recovery scratch before its first mutation.
If a later section unexpectedly fails, every already-mutated section is
restored. An invalid/corrupt visual payload regression proves that a failed
composite restore leaves simulation, pixels, presenter history, and semantic
audio state exactly as they were before the call.

## Memory and verification

The current GCC x64 snapshot is 634,988 bytes. Sixteen slots reserve 10,159,808
bytes; one additional reusable recovery image brings the process-state budget
to 10,794,796 bytes. These are implementation measurements, not a serialized
ABI or protocol limit.

The cross-compiler MAIN regression creates two identical retained processes,
captures one, deliberately diverges it for five frames, restores it, and then
proves that the corrected next frame matches uninterrupted execution in:

- `StepResult` boundary facts and canonical simulation hash;
- all 256,000 composed source pixels;
- the complete next process snapshot; and
- every undelivered semantic audio command.

`T3RBC001.md` now puts these images into a preallocated frame ring, performs
one private rollback on every test frame, withholds private speculative video
and audio, publishes only corrected state, and measures the complete local
path. Asynchronous confirmation and the final responsive SFX event journal
remain network-session policy rather than process-state ownership.
